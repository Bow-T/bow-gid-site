The problem

AI coding agents got good enough to trust with real work, and that is exactly the problem. The moment an agent can edit files, run shell commands, and push migrations, “let it run and see” stops being a strategy — so you babysit a terminal, and everyone else on the team gets either no access to the agent or an access level that terrifies you.

bow-gid runs on your machine and puts one permission boundary between the agent and anything that writes. Your QC engineer, your BA, your tech lead, and your contractor all work through it — each with only the reach their job needs.

How much rope

Four modes and two switches. One list of brakes that never lifts.

Per tabRuns on its ownStill stops for you
Plan Reads, search, safe shell — then a written plan Every write. Plan mode only plans.
Manual Reads, plus safe test / build / type-check commands Every edit and every command with side effects
Edit-auto File edits inside the repo Shell with side effects, anything outside the repo
Auto Edits plus non-destructive shell Risky actions — rm -rf, git push, writes outside the repo
Auto-approve Anything you could undo — and it carries the task through commit → push the work branch → open the merge request Choosing between approaches: it asks you
Autopilot Picks the approach itself and re-checks every acceptance clause before it opens the MR — under a per-turn cost cap The hard brakes below

Hard brakes, in every mode: deleting files that existed before the turn, discarding uncommitted work (reset --hard, clean), force-push, anything on the main branch, merging or closing a merge request, writing to a database, sudo. The agent opens merge requests; merging is a human's job.

What else is in the box

Built for the whole loop, from ticket to merge request.

Ticket → MR

Paste a Jira URL

It pulls the ticket, acceptance criteria, screenshots and video attachments, splits the ticket into clauses, and reports each one as done, unverified or missing — with a hand-off note for QC.

Queue

Tickets, one after another

Queue a sprint's tickets and walk away; each runs unattended in its own worktree through to a merge request. Sprint-scan triages on a schedule and asks the reporter when a ticket is unclear; one click checks the whole sprint for duplicate tickets.

Agent crew

Reviewers that argue back

A reviewer attacks the plan, a verifier traces runtime behaviour, a challenger writes adversarial tests, a scout finds every call site. All read-only — and with the crew on, the agent is sent back to get the latest diff reviewed before it commits.

Test

On a simulator or in a browser

A test turn drives your iOS Simulator or a web page like a QA engineer would, records the video, and saves a script you can replay. Taps on risky buttons still stop for approval.

Group chat

Bow Agent in the room

Team rooms plus a private “Ask Bow”. It reads committed code and queries your database read-only — secrets blocked, results masked — and drafts Jira tickets that go out only after someone approves the card.

Desktop app

Their tools stay on their machine

Teammates join your Host from the bow-gid app. Their own connectors — Notion, Linear, Jira, Figma, Miro — sign in on their machine, and the token never leaves it. The Host sees each call the agent makes through them, and logs it.

Phone

The card follows you

A card left waiting (20 s by default) or a long run finishing pings your phone through the companion app and your own Firebase project. On Android, with phone approval switched on, routine cards can be answered from the notification; risky ones open the app behind your fingerprint. The push names only the event and the task; what the agent wants to run travels encrypted.

Daily

Today, Release, Design

Today plans your day from Jira due dates and estimates. Release runs your project's own release script with the flags you pick. Designs keeps UI drafts in the repo, next to the code.

Models

Pick per tab

Claude through your existing subscription, or another model through a gateway — chosen per tab. Long sessions compact themselves instead of dying, and a hit usage cap schedules a resume.

FAQ

Questions people ask first.

Do I need an API key?

No. bow-gid runs on the Claude Agent SDK with your existing Claude login. You can also pick another model through a gateway, per tab.

Where does my code go?

Your repos stay on your disk, and there is no bow-gid server and no account. What the agent reads is sent to the model you picked, as it would be from Claude Code. A teammate's own connectors sign in on their machine, and the token never leaves it.

Can the agent push to main or merge?

No. Anything on the main branch, force-push, and merging or closing a merge request are hard brakes in every mode. With Auto-approve on it pushes its own work branch and opens the merge request; merging is yours.

What happens when I press Deny?

Nothing is written — not one byte. The agent is told no, and it has to find another way or ask you.

Can it work while nobody is watching?

Queued tickets run unattended, each in its own worktree with its own cost cap — and the hard brakes still stop them. A teammate is bounded by the seat you granted; a contractor's every write waits for your live approval.

GitHub or GitLab?

Both. It opens pull requests with gh and merge requests with glab.

What does it run on?

The host needs Node ≥ 22; bow-gid is built and used on macOS, and simulator test turns need Xcode's iOS Simulator, so a Mac. Teammates need only a browser or the bow-gid desktop app.
